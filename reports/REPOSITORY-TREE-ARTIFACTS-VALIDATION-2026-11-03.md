# Repository tree artifacts and project grouping — validation

**Date:** 2026-11-03  
**Branch:** `feat/repository-project-trees-2026-11-03`  
**Base:** DGM-MAT main after PR #170 and PR #171.

## Delivered

- Every non-protected repository receives a UTF-8 `.tree.txt` sidecar in a central artifact directory.
- Tree generation reads directory entries only; it does not read file contents or alter source repositories.
- Stable path hashes prevent collisions between repositories with the same directory name.
- Trees are bounded to 4,000 entries and 12 directory levels.
- Git metadata, build output, dependencies, virtual environments, secret/credential files, private keys and symlinks are excluded.
- Existing trees are reused for unchanged repositories; changed repositories regenerate their tree.
- Tree metadata is indexed in SQLite and exposed through the repository inventory API.
- A bounded API route returns a tree only when its repository is already indexed and the artifact path is within the configured tree directory.
- Project-group suggestions use strong evidence only: same Git origin (0.99) or sibling repositories under a non-root parent directory (0.85). Single repositories remain separate and marked for semantic review (0.25).
- The API returns project-group summaries and defaults to a 200-repository page.
